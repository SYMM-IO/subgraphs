# 0.8.5 Migration Guide

## Removed `QuotePriceUpdate` Entity

The `QuotePriceUpdate` entity has been removed. It was a flat log of every price change on a quote (from funding rate charges and upnl settlements). This data is now covered by the `QuoteEvent` entity, which provides a unified timeline of all quote lifecycle events including price changes.

### Field Mapping

| QuotePriceUpdate | QuoteEvent |
|---|---|
| `quoteId` | `quoteId` |
| `prevPrice` | `metadata.prevPrice` |
| `newPrice` | `metadata.newPrice` |
| `openQuantity` | `metadata.openQuantity` |
| `timestamp` | `timestamp` |
| `source` | `source` |
| `type = "ChargeFundingRate"` | `type = "CHARGE_FUNDING_RATE"` |
| `type = "SettleUpnl"` | `type = "SETTLE_UPNL"` |
| `type = "SettleUpnlUnified"` | `type = "SETTLE_UPNL"` |

### Additional Fields Available

`QuoteEvent` also provides: `quote` (entity link), `blockNumber`, `transaction`.

Funding events (`CHARGE_FUNDING_RATE`, `CHARGE_ACCUMULATED_FUNDING_FEE`) include additional metadata: `rate`, `fundingPaid`, `fundingReceived`.

### Migration

Replace `quotePriceUpdates` queries with `quoteEvents` filtered by the relevant types.

Before:
```graphql
{
  quotePriceUpdates(where: { quoteId: "123" }, orderBy: timestamp) {
    prevPrice
    newPrice
    openQuantity
    type
    timestamp
  }
}
```

After:
```graphql
{
  quoteEvents(
    where: {
      quoteId: "123",
      type_in: ["CHARGE_FUNDING_RATE", "CHARGE_ACCUMULATED_FUNDING_FEE", "SETTLE_UPNL"]
    },
    orderBy: timestamp
  ) {
    type
    metadata
    timestamp
    blockNumber
    transaction
  }
}
```

## New `QuoteEvent` Entity

A new immutable `QuoteEvent` entity provides a unified timeline of every lifecycle event on a quote. Each event carries a `type` string and an optional `metadata` JSON blob with event-specific fields.

### Schema

```graphql
type QuoteEvent @entity(immutable: true) {
  id: ID!
  source: Bytes!
  quoteId: BigInt!
  quote: Quote!
  type: String!
  metadata: String
  timestamp: BigInt!
  blockNumber: BigInt!
  transaction: Bytes!
}
```

### Event Types & Metadata

| Type | Metadata fields |
|---|---|
| `SEND_QUOTE` | `symbolId`, `quantity`, `requestedOpenPrice`, `positionType`, `orderType`?, `cva`?, `lf`?, `partyAmm`?, `partyBmm`?, `deadline`? |
| `LOCK_QUOTE` | `partyB` |
| `UNLOCK_QUOTE` | — |
| `OPEN_POSITION` | `filledAmount`, `openedPrice`, `cva`?, `lf`?, `partyAmm`?, `partyBmm`? |
| `REQUEST_TO_CLOSE` | `closePrice`, `quantityToClose`, `orderType`, `deadline`? |
| `REQUEST_TO_CANCEL_QUOTE` | — |
| `REQUEST_TO_CANCEL_CLOSE` | — |
| `ACCEPT_CANCEL_QUOTE` | — |
| `ACCEPT_CANCEL_CLOSE` | — |
| `FORCE_CANCEL_QUOTE` | — |
| `FORCE_CANCEL_CLOSE` | — |
| `FILL_CLOSE` | `amount`, `closePrice`, `quoteStatus` |
| `FORCE_CLOSE` | `amount`, `closePrice`, `quoteStatus` |
| `EMERGENCY_CLOSE` | `amount`, `closePrice`, `quoteStatus` |
| `ADL_CLOSE` | `amount`, `closePrice` |
| `FORCE_CLOSE_INSOLVENT` | `amount`, `closedPrice` |
| `LIQUIDATE_PARTY_A` | `amount`, `closePrice` |
| `LIQUIDATE_PARTY_B` | `amount`, `closePrice` |
| `LIQUIDATE_CLEARING_HOUSE` | `amount`, `closePrice` |
| `LIQUIDATE_PENDING` | — |
| `EXPIRE_QUOTE` | `quoteStatus` |
| `EXPIRE_QUOTE_OPEN` | — |
| `EXPIRE_QUOTE_CLOSE` | — |
| `CHARGE_FUNDING_RATE` | `rate`, `fundingPaid`, `fundingReceived`, `prevPrice`, `newPrice`, `openQuantity` |
| `CHARGE_ACCUMULATED_FUNDING_FEE` | `fundingPaid`, `fundingReceived`, `prevPrice`, `newPrice`, `openQuantity` |
| `SETTLE_UPNL` | `prevPrice`, `newPrice`, `openQuantity` |

Fields marked with `?` are nullable and only present when the value is available.

### Example Query

```graphql
{
  quoteEvents(where: { quoteId: "123" }, orderBy: timestamp) {
    type
    metadata
    timestamp
    blockNumber
    transaction
  }
}
```

## Removed `TradeHistory` Entity

The `TradeHistory` entity has been removed. It tracked per-quote cumulative volume and status across open/close/liquidation events. This data is already available through `CloseHistory` (individual close/liquidation records) and the `Quote` entity itself.

### Field Mapping

| TradeHistory field | Alternative |
|---|---|
| `account` | `CloseHistory.account` or `Quote.partyA` |
| `volume` | Sum of `CloseHistory.volume` records for that quote, plus `Quote.openedPrice * Quote.quantity` for the open |
| `quoteStatus` | `Quote.quoteStatus` (always current) |
| `quote` | `CloseHistory.quoteId` / `CloseHistory.quote` |
| `timestamp` | `CloseHistory.timestamp` for each close event |
| `blockNumber` | `CloseHistory.blockNumber` |
| `transaction` | `CloseHistory.transaction` |

### Migration

The `Quote` entity holds the current status and opened price/quantity. `CloseHistory` records each fill/liquidation with its volume, price, and close type. Together they provide more detail than `TradeHistory` did.

Before:
```graphql
{
  tradeHistories(where: { account: "0x..." }) {
    quote
    volume
    quoteStatus
    timestamp
  }
}
```

After:
```graphql
{
  closeHistories(where: { account: "0x..." }, orderBy: timestamp) {
    quoteId
    quote { quoteStatus }
    volume
    closePrice
    closeType
    timestamp
  }
}
```

## New `LatestAccountBalance` Entity

A new mutable entity that tracks the real-time balance state of every account in the system. It reads the full balance breakdown from the contract's `balanceInfoOfPartyA` / `balanceInfoOfPartyB` view functions and updates on every event that mutates allocated, locked, or pending locked balances.

### Schema

```graphql
type LatestAccountBalance @entity(immutable: false) {
  id: ID!
  source: Bytes!
  account: Bytes!
  counterParty: Bytes
  accountType: String!
  allocatedBalance: BigInt!
  lockedCva: BigInt!
  lockedLf: BigInt!
  lockedPartyAmm: BigInt!
  lockedPartyBmm: BigInt!
  pendingLockedCva: BigInt!
  pendingLockedLf: BigInt!
  pendingLockedPartyAmm: BigInt!
  pendingLockedPartyBmm: BigInt!
  timestamp: BigInt!
  blockNumber: BigInt!
  transaction: Bytes!
}
```

### Entity Types

There are two types of entities, distinguished by the `accountType` field:

| `accountType` | ID format | Description |
|---|---|---|
| `"PartyA"` | `{partyA}-{contract}` | PartyA's own balance state |
| `"PartyB"` | `{partyB}-{partyA}-{contract}` | PartyB's balance state relative to a specific PartyA (isolated mode) |

- **`account`**: The primary account address (PartyA or PartyB).
- **`counterParty`**: Only set for PartyB entities — the PartyA address this balance is relative to. Null for PartyA entities.

### Balance Fields

All 9 fields come directly from the contract's `balanceInfoOfPartyA(address)` or `balanceInfoOfPartyB(address, address)` view functions:

| Field | Description |
|---|---|
| `allocatedBalance` | Funds allocated for trading |
| `lockedCva` | Credit Valuation Adjustment locked in open positions |
| `lockedLf` | Liquidation Fee locked in open positions |
| `lockedPartyAmm` | PartyA maintenance margin locked in open positions |
| `lockedPartyBmm` | PartyB maintenance margin locked in open positions |
| `pendingLockedCva` | CVA locked in pending (not yet opened) quotes |
| `pendingLockedLf` | LF locked in pending quotes |
| `pendingLockedPartyAmm` | PartyA MM locked in pending quotes |
| `pendingLockedPartyBmm` | PartyB MM locked in pending quotes |

### Trigger Events

The entity updates on every event that can change any of the above fields. This includes allocations, deallocations, quote lifecycle events (send, open, cancel, close, expire), funding rate charges, settlements, and all liquidation events. The full list per ABI version is in the `deps_symmio_*.json` files under the `LatestAccountBalance` key.

### Example Queries

Get a PartyA's current balance:
```graphql
{
  latestAccountBalance(id: "0xPartyA-0xContract") {
    allocatedBalance
    lockedCva
    lockedLf
    lockedPartyAmm
    lockedPartyBmm
    pendingLockedCva
    pendingLockedLf
    pendingLockedPartyAmm
    pendingLockedPartyBmm
    timestamp
  }
}
```

Get all PartyB balances for a specific PartyA:
```graphql
{
  latestAccountBalances(where: { counterParty: "0xPartyA", accountType: "PartyB" }) {
    account
    allocatedBalance
    lockedCva
    lockedLf
    lockedPartyAmm
    lockedPartyBmm
    timestamp
  }
}
```
