# 0.8.5 Migration Guide

## Removed `QuotePriceUpdate` Entity

The `QuotePriceUpdate` entity has been removed. It was a flat log of every price change on a quote (from funding rate charges and upnl settlements). This data is now covered by the `QuoteEvent` entity, which provides a unified timeline of all quote lifecycle events including price changes.

### Field Mapping

| QuotePriceUpdate | QuoteEvent |
|---|---|
| `quoteId` | `quoteId` |
| `prevPrice` | `metadata.prevPrice` |
| `newPrice` | `metadata.newPrice` |
| `openQuantity` | `metadata.openQuantity` |
| `timestamp` | `timestamp` |
| `source` | `source` |
| `type = "ChargeFundingRate"` | `type = "CHARGE_FUNDING_RATE"` |
| `type = "SettleUpnl"` | `type = "SETTLE_UPNL"` |
| `type = "SettleUpnlUnified"` | `type = "SETTLE_UPNL"` |

### Additional Fields Available

`QuoteEvent` also provides: `quote` (entity link), `blockNumber`, `transaction`.

Funding events (`CHARGE_FUNDING_RATE`, `CHARGE_ACCUMULATED_FUNDING_FEE`) include additional metadata: `rate`, `fundingPaid`, `fundingReceived`.

### Migration

Replace `quotePriceUpdates` queries with `quoteEvents` filtered by the relevant types.

Before:
```graphql
{
  quotePriceUpdates(where: { quoteId: "123" }, orderBy: timestamp) {
    prevPrice
    newPrice
    openQuantity
    type
    timestamp
  }
}
```

After:
```graphql
{
  quoteEvents(
    where: {
      quoteId: "123",
      type_in: ["CHARGE_FUNDING_RATE", "CHARGE_ACCUMULATED_FUNDING_FEE", "SETTLE_UPNL"]
    },
    orderBy: timestamp
  ) {
    type
    metadata
    timestamp
    blockNumber
    transaction
  }
}
```

## New `QuoteEvent` Entity

A new immutable `QuoteEvent` entity provides a unified timeline of every lifecycle event on a quote. Each event carries a `type` string and an optional `metadata` JSON blob with event-specific fields.

### Schema

```graphql
type QuoteEvent @entity(immutable: true) {
  id: ID!
  source: Bytes!
  quoteId: BigInt!
  quote: Quote!
  type: String!
  metadata: String
  timestamp: BigInt!
  blockNumber: BigInt!
  transaction: Bytes!
}
```

### Event Types & Metadata

| Type | Metadata fields |
|---|---|
| `SEND_QUOTE` | `symbolId`, `quantity`, `requestedOpenPrice`, `positionType`, `orderType`?, `cva`?, `lf`?, `partyAmm`?, `partyBmm`?, `deadline`? |
| `LOCK_QUOTE` | `partyB` |
| `UNLOCK_QUOTE` | — |
| `OPEN_POSITION` | `filledAmount`, `openedPrice`, `cva`?, `lf`?, `partyAmm`?, `partyBmm`? |
| `REQUEST_TO_CLOSE` | `closePrice`, `quantityToClose`, `orderType`, `deadline`? |
| `REQUEST_TO_CANCEL_QUOTE` | — |
| `REQUEST_TO_CANCEL_CLOSE` | — |
| `ACCEPT_CANCEL_QUOTE` | — |
| `ACCEPT_CANCEL_CLOSE` | — |
| `FORCE_CANCEL_QUOTE` | — |
| `FORCE_CANCEL_CLOSE` | — |
| `FILL_CLOSE` | `amount`, `closePrice`, `quoteStatus` |
| `FORCE_CLOSE` | `amount`, `closePrice`, `quoteStatus` |
| `EMERGENCY_CLOSE` | `amount`, `closePrice`, `quoteStatus` |
| `ADL_CLOSE` | `amount`, `closePrice` |
| `LIQUIDATE_PARTY_A` | `amount`, `closePrice` |
| `LIQUIDATE_PARTY_B` | `amount`, `closePrice` |
| `LIQUIDATE_CLEARING_HOUSE` | `amount`, `closePrice` |
| `LIQUIDATE_PENDING` | — |
| `EXPIRE_QUOTE` | `quoteStatus` |
| `EXPIRE_QUOTE_OPEN` | — |
| `EXPIRE_QUOTE_CLOSE` | — |
| `CHARGE_FUNDING_RATE` | `rate`, `fundingPaid`, `fundingReceived`, `prevPrice`, `newPrice`, `openQuantity` |
| `CHARGE_ACCUMULATED_FUNDING_FEE` | `fundingPaid`, `fundingReceived`, `prevPrice`, `newPrice`, `openQuantity` |
| `SETTLE_UPNL` | `prevPrice`, `newPrice`, `openQuantity` |

Fields marked with `?` are nullable and only present when the value is available.

### Example Query

```graphql
{
  quoteEvents(where: { quoteId: "123" }, orderBy: timestamp) {
    type
    metadata
    timestamp
    blockNumber
    transaction
  }
}
```

## Removed `TradeHistory` Entity

The `TradeHistory` entity has been removed. It tracked per-quote cumulative volume and status across open/close/liquidation events. This data is now available through `QuoteEvent` (individual lifecycle records) and the `Quote` entity itself.

### Field Mapping

| TradeHistory field | Alternative |
|---|---|
| `account` | `Quote.partyA` |
| `volume` | Computed from `QuoteEvent` metadata: `amount * closePrice` for close/liquidation events, `Quote.openedPrice * Quote.quantity` for the open |
| `quoteStatus` | `Quote.quoteStatus` (always current) |
| `quote` | `QuoteEvent.quote` / `QuoteEvent.quoteId` |
| `timestamp` | `QuoteEvent.timestamp` |
| `blockNumber` | `QuoteEvent.blockNumber` |
| `transaction` | `QuoteEvent.transaction` |

### Migration

The `Quote` entity holds the current status and opened price/quantity. `QuoteEvent` records each lifecycle event including fills, closes, and liquidations with their metadata. Together they provide more detail than `TradeHistory` did.

Before:
```graphql
{
  tradeHistories(where: { account: "0x..." }) {
    quote
    volume
    quoteStatus
    timestamp
  }
}
```

After:
```graphql
{
  quoteEvents(
    where: {
      type_in: ["OPEN_POSITION", "FILL_CLOSE", "FORCE_CLOSE", "EMERGENCY_CLOSE",
                 "ADL_CLOSE", "LIQUIDATE_PARTY_A", "LIQUIDATE_PARTY_B",
                 "LIQUIDATE_CLEARING_HOUSE"]
    },
    orderBy: timestamp
  ) {
    quoteId
    quote { quoteStatus, partyA }
    type
    metadata
    timestamp
  }
}
```

## New `LatestAccountBalance` Entity

A new mutable entity that tracks the real-time balance state of every account in the system. It reads the full balance breakdown from the contract's `balanceInfoOfPartyA` / `balanceInfoOfPartyB` view functions and updates on every event that mutates allocated, locked, or pending locked balances.

### Schema

```graphql
type LatestAccountBalance @entity(immutable: false) {
  id: ID!
  source: Bytes!
  account: Bytes!
  counterParty: Bytes
  accountType: String!
  allocatedBalance: BigInt!
  lockedCva: BigInt!
  lockedLf: BigInt!
  lockedPartyAmm: BigInt!
  lockedPartyBmm: BigInt!
  pendingLockedCva: BigInt!
  pendingLockedLf: BigInt!
  pendingLockedPartyAmm: BigInt!
  pendingLockedPartyBmm: BigInt!
  timestamp: BigInt!
  blockNumber: BigInt!
  transaction: Bytes!
}
```

### Entity Types

There are two types of entities, distinguished by the `accountType` field:

| `accountType` | ID format | Description |
|---|---|---|
| `"PartyA"` | `{partyA}-{contract}` | PartyA's own balance state |
| `"PartyB"` | `{partyB}-{partyA}-{contract}` | PartyB's balance state relative to a specific PartyA (isolated mode) |

- **`account`**: The primary account address (PartyA or PartyB).
- **`counterParty`**: Only set for PartyB entities — the PartyA address this balance is relative to. Null for PartyA entities.

### Balance Fields

All 9 fields come directly from the contract's `balanceInfoOfPartyA(address)` or `balanceInfoOfPartyB(address, address)` view functions:

| Field | Description |
|---|---|
| `allocatedBalance` | Funds allocated for trading |
| `lockedCva` | Credit Valuation Adjustment locked in open positions |
| `lockedLf` | Liquidation Fee locked in open positions |
| `lockedPartyAmm` | PartyA maintenance margin locked in open positions |
| `lockedPartyBmm` | PartyB maintenance margin locked in open positions |
| `pendingLockedCva` | CVA locked in pending (not yet opened) quotes |
| `pendingLockedLf` | LF locked in pending quotes |
| `pendingLockedPartyAmm` | PartyA MM locked in pending quotes |
| `pendingLockedPartyBmm` | PartyB MM locked in pending quotes |

### Trigger Events

The entity updates on every event that can change any of the above fields. This includes allocations, deallocations, quote lifecycle events (send, open, cancel, close, expire), funding rate charges, settlements, and all liquidation events. The full list per ABI version is in the `deps_symmio_*.json` files under the `LatestAccountBalance` key.

### Example Queries

Get a PartyA's current balance:
```graphql
{
  latestAccountBalance(id: "0xPartyA-0xContract") {
    allocatedBalance
    lockedCva
    lockedLf
    lockedPartyAmm
    lockedPartyBmm
    pendingLockedCva
    pendingLockedLf
    pendingLockedPartyAmm
    pendingLockedPartyBmm
    timestamp
  }
}
```

Get all PartyB balances for a specific PartyA:
```graphql
{
  latestAccountBalances(where: { counterParty: "0xPartyA", accountType: "PartyB" }) {
    account
    allocatedBalance
    lockedCva
    lockedLf
    lockedPartyAmm
    lockedPartyBmm
    timestamp
  }
}
```

## Account Layer: SubAccount & VirtualAccount Model

The Account Layer introduces a hierarchical account structure on top of the base SYMMIO trading system. Affiliates manage SubAccounts, which in turn can spawn VirtualAccounts for isolated trading positions.

### Entity Hierarchy

```
Affiliate
  └── SubAccount (1:N)
        └── VirtualAccount (1:N)
```

- An **Affiliate** is a registered frontend/integration partner.
- A **SubAccount** belongs to exactly one Affiliate and represents a user's trading identity under that affiliate.
- A **VirtualAccount** belongs to exactly one SubAccount (its `parent`) and provides an isolated address for individual positions or strategies.

### Entity Schemas

#### SubAccount

```graphql
type SubAccount @entity(immutable: false) {
  id: ID!
  address: Bytes!
  owner: Bytes!
  affiliate: Affiliate!
  name: String
  singleVAMode: Boolean!
  isDeleted: Boolean!
  source: Bytes!
  timestamp: BigInt!
  updateTimestamp: BigInt!
  virtualAccounts: [VirtualAccount!]! @derivedFrom(field: "parent")
  marginTransfers: [MarginTransfer!]! @derivedFrom(field: "subAccount")
  quotes: [Quote!]! @derivedFrom(field: "subAccount")
}
```

| Field | Description |
|---|---|
| `address` | On-chain address of the SubAccount |
| `owner` | Wallet address that owns this SubAccount |
| `affiliate` | The Affiliate this SubAccount is registered under |
| `name` | Optional display name |
| `singleVAMode` | When true, the SubAccount uses a single VirtualAccount for all positions |
| `isDeleted` | Soft-delete flag (set by `SubAccountDeleted` events) |
| `virtualAccounts` | All VirtualAccounts under this SubAccount (derived) |
| `marginTransfers` | All margin transfers involving this SubAccount (derived) |
| `quotes` | All quotes belonging to this SubAccount or its VirtualAccounts (derived) |

#### VirtualAccount

```graphql
type VirtualAccount @entity(immutable: false) {
  id: ID!
  address: Bytes!
  parent: SubAccount!
  isDeleted: Boolean!
  source: Bytes!
  timestamp: BigInt!
  updateTimestamp: BigInt!
  marginTransfers: [MarginTransfer!]! @derivedFrom(field: "virtualAccount")
}
```

| Field | Description |
|---|---|
| `address` | On-chain address of the VirtualAccount |
| `parent` | The SubAccount this VirtualAccount belongs to |
| `isDeleted` | Soft-delete flag (set by `VirtualAccountDeleted` events) |
| `marginTransfers` | All margin transfers involving this VirtualAccount (derived) |

#### MarginTransfer

```graphql
type MarginTransfer @entity(immutable: true) {
  id: ID!
  type: String!
  virtualAccount: VirtualAccount!
  subAccount: SubAccount!
  amount: BigInt!
  source: Bytes!
  timestamp: BigInt!
  blockNumber: BigInt!
  transaction: Bytes!
}
```

Immutable event log recording margin movements between the SubAccount and its VirtualAccounts.

### Relationships with Other Entities

#### Account

The `Account` entity is the base trading identity in the subgraph. It bridges to the Account Layer via two optional fields:

```
Account.subAccount  → SubAccount  (nullable)
Account.virtualAccount → VirtualAccount (nullable)
```

- If the account **is** a SubAccount, `account.subAccount` points to itself.
- If the account **is** a VirtualAccount, `account.subAccount` points to its parent SubAccount, and `account.virtualAccount` points to itself.
- Legacy accounts (created before the Account Layer) have both fields as null.

#### Quote

The `Quote` entity has an optional `subAccount` field:

```
Quote.subAccount → SubAccount (nullable)
```

This is set at quote creation time (`SendQuote`) by reading the Account's `subAccount` reference. This means:
- Quotes sent by a SubAccount directly are linked to that SubAccount.
- Quotes sent by a VirtualAccount are linked to the VirtualAccount's parent SubAccount.
- Legacy quotes (no Account Layer) have `subAccount` as null.

The `SubAccount.quotes` derived field returns all quotes linked to it, including quotes from all of its VirtualAccounts.

#### Affiliate

```
Affiliate.subAccounts → [SubAccount!]! @derivedFrom(field: "affiliate")
```

An Affiliate can traverse down to all its SubAccounts, and from there to their VirtualAccounts and quotes.

### Relationship Diagram

```
Affiliate
  │
  ├── subAccounts (derived)
  │     │
  │     └── SubAccount
  │           ├── virtualAccounts (derived) ──→ [VirtualAccount]
  │           ├── marginTransfers (derived) ──→ [MarginTransfer]
  │           ├── quotes (derived) ──────────→ [Quote]  (includes quotes from all VirtualAccounts)
  │           │
  │           └── ◄── Account.subAccount
  │
  VirtualAccount
        ├── parent ──→ SubAccount
        ├── marginTransfers (derived) ──→ [MarginTransfer]
        │
        └── ◄── Account.virtualAccount

  MarginTransfer
        ├── subAccount ──→ SubAccount
        └── virtualAccount ──→ VirtualAccount

  Quote
        └── subAccount ──→ SubAccount (nullable)

  Account
        ├── subAccount ──→ SubAccount (nullable)
        └── virtualAccount ──→ VirtualAccount (nullable)
```

### Example Queries

Get a SubAccount with all its quotes (including from VirtualAccounts):
```graphql
{
  subAccount(id: "0x...") {
    address
    name
    owner
    affiliate { name }
    singleVAMode
    quotes {
      quoteId
      quoteStatus
      partyA
      symbolId
      quantity
      requestedOpenPrice
    }
    virtualAccounts {
      address
      isDeleted
    }
  }
}
```

Get all SubAccounts for an Affiliate:
```graphql
{
  affiliate(id: "0x...") {
    name
    subAccounts {
      address
      name
      quotes { quoteId }
      virtualAccounts { address }
    }
  }
}
```

Get margin transfers for a SubAccount:
```graphql
{
  subAccount(id: "0x...") {
    marginTransfers(orderBy: timestamp, orderDirection: desc) {
      type
      amount
      virtualAccount { address }
      timestamp
      transaction
    }
  }
}
```

Find the SubAccount for a given Quote:
```graphql
{
  quote(id: "123-0xContract") {
    quoteId
    partyA
    subAccount {
      address
      name
      affiliate { name }
    }
  }
}
```

## Removed Redundant Quote Timestamp and Transaction Hash Fields

The Quote entity previously carried ~45 event-specific fields (23 `timestamp*` + 22 `txHash*`) that recorded when each lifecycle event occurred and its transaction hash. These fields are now redundant because `QuoteEvent` entities provide an immutable audit log of every lifecycle event with `timestamp`, `blockNumber`, and `transaction` hash.

### Retained Fields

Three timestamp fields are kept on the Quote entity:

| Field | Purpose |
|---|---|
| `timestamp` | Last-updated timestamp (set on every event) |
| `timestampSendQuote` | When the quote was created — useful for sorting/filtering by creation time |
| `timestampOpenPosition` | When the position was opened — useful for sorting/filtering by open time |

### Removed Fields

**Timestamp fields removed (20):**
`timestampLastFundingPayment`, `timestampExpireQuote`, `timestampAcceptCancelCloseRequest`, `timestampAcceptCancelRequest`, `timestampChargeFundingRate`, `timestampEmergencyClosePosition`, `timestampForceCancelCloseRequest`, `timestampFillCloseRequest`, `timestampForceCancelQuote`, `timestampForceClosePosition`, `timestampLockQuote`, `timestampRequestToCancelCloseRequest`, `timestampRequestToCancelQuote`, `timestampRequestToLimitClosePosition`, `timestampUnlockQuote`, `timestampSettleUpnl`, `timestampRequestToClosePosition`, `timestampLiquidatePendingPositionsPartyA`, `timestampLiquidatePositionsPartyA`, `timestampLiquidatePositionsPartyB`

**Transaction hash fields removed (21):**
`txHashExpireQuote`, `txHashAcceptCancelCloseRequest`, `txHashAcceptCancelRequest`, `txHashChargeFundingRate`, `txHashEmergencyClosePosition`, `txHashForceCancelCloseRequest`, `txHashFillCloseRequest`, `txHashForceCancelQuote`, `txHashForceClosePosition`, `txHashLockQuote`, `txHashRequestToCancelCloseRequest`, `txHashOpenPosition`, `txHashRequestToCancelQuote`, `txHashSendQuote`, `txHashRequestToLimitClosePosition`, `txHashUnlockQuote`, `txHashSettleUpnl`, `txHashRequestToClosePosition`, `txHashLiquidatePendingPositionsPartyA`, `txHashLiquidatePositionsPartyA`, `txHashLiquidatePositionsPartyB`

### Migration

Use `quoteEvents` (the derived field on Quote) to get event timestamps and transaction hashes.

Before:
```graphql
{
  quote(id: "123-0xContract") {
    timestampLockQuote
    txHashLockQuote
    timestampFillCloseRequest
    txHashFillCloseRequest
  }
}
```

After:
```graphql
{
  quoteEvents(
    where: { quoteId: "123", type_in: ["LOCK_QUOTE", "FILL_CLOSE"] },
    orderBy: timestamp
  ) {
    type
    timestamp
    blockNumber
    transaction
  }
}
```
